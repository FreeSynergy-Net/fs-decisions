## 0.0.1

The first version of this repository (it was empty before). The tag is set by the project owner; the release (signing) waits until the signing environment of this new repository is set up by the owner.

### English

- **Window and server (basics, workflow `grundfassung`).** New workspace with four crates: `fs-decisions-server` (the contract `surveys.capnp` draft 0.1 over a local socket through `fs-rpc` v0.0.2; `capabilities` answers a `CapabilityList` with no capability ids and the contract version `0.1`, and `supportReport`; everything else is `unimplemented`), `fs-decisions-client` (connect with the version handshake, `Hello::fetch` with a limit of 15 s for the first conversation so a hanging instance ends with an error, contract check: same main level, minor level of the server not lower; errors have a code and a detail), `fs-decisions-simple` (the frontend `simple` as a process of its own; depends only on the client and fs-components v0.0.25), `fs-decisions-bin` (the command `fs-decisions`: starter, `serve`, `--version`, `--help`). There is no core crate yet: counting votes stays in `fs-forms-methods` (fs-forms) until the move to `fs-tally` and `fs-ballot` (plan steps D1 and D2); nothing is moved in this version.
- **Main view (preview).** The page "Decisions" shows a date poll grid in the manner of Doodle (participants by time windows, answers Yes, If needed, No in words, counts apart, suggested window with its rule next to it) and the list "my decisions". All of it is typed sample data ("Example A" to "Example D"), marked "Preview" (banner, window title) and "Example"; `mode(capabilities)` hides it as soon as the server offers `decision.read`. Missing components are listed as gaps in DESIGN.md.
- **Suggestion rule (owner decision 2026-11-17).** The window with the most commitments (Yes plus If needed); on a tie the one with fewer "If needed", then the earliest. "If needed" is not weighted; the rule is shown with the suggestion. A person fixes the date.
- **Window.** Pages Start, Decisions and What comes (`--screen start|main|coming`); the icon of 64 px sits directly at the title; "Goal:" before the goal sentence; everything not built says "coming soon", the open points say "planned, not scheduled".
- **Starter.** `fs-decisions` starts or replaces the server (handshake of `fs-rpc`), asks the frontend to check the contract (`--check`, exit code 3 = does not fit) and falls back to the standard frontend `simple` with a visible message. Errors in the window and on stderr are a code with parameters; the words are the program's own (MessageFormat 2, German and English).
- **Pins, one source per library:** `fs-interfaces` v0.0.27, `fs-rpc` v0.0.2, `fs-components` v0.0.25 (`fs-types` and `fs-objects` through them). `.fs-lock-sources.toml` strict. Minimum Rust 1.89.
- **CI:** `check.yml` and `release.yml` call fs-release at `v0.0.10`. Linux only (`windows-targets` empty: Unix sockets). Release after the owner has set up the signing environment.
- The icon (`packaging/net.freesynergy.Decisions.png`, `.desktop`, embedded in the window); `fs-decisions` depends on the package `fs-decisions-simple` (deb `depends`, rpm `requires`).
- Contract: draft (`surveys.capnp`, not locked). The basics are released with this draft contract. The capability key stays `surveys` (display name "Decisions", ADR 0068).
- Not done: no data goes through the contract, no lease (the server keeps running after the window closes until it is stopped or replaced), the sample is not switchable by a button yet, no picture of the empty state.

### Deutsch

Die erste Version dieses Repositories (es war vorher leer). Den Tag setzt der Projektinhaber; das Release (Signierung) wartet, bis der Inhaber die Signier-Umgebung dieses neuen Repositories eingerichtet hat.

- **Fenster und Server (Grundfassung, Workflow `grundfassung`).** Neuer Arbeitsbereich mit vier Crates: `fs-decisions-server` (der Vertrag `surveys.capnp` Entwurf 0.1 über einen lokalen Socket mit `fs-rpc` v0.0.2; `capabilities` antwortet mit einer `CapabilityList` ohne Fähigkeits-Kennungen und der Vertragsversion `0.1`, dazu `supportReport`; alles andere ist `unimplemented`), `fs-decisions-client` (Verbinden mit Versions-Handschlag, `Hello::fetch` mit einer Frist von 15 s für das erste Gespräch, damit eine hängende Instanz mit einem Fehler endet, Vertragsprüfung: gleiche Hauptstufe, Nebenstufe des Servers nicht niedriger; Fehler haben Code und Detail), `fs-decisions-simple` (das Frontend `simple` als eigener Prozess; hängt nur am Client und an fs-components v0.0.25), `fs-decisions-bin` (der Befehl `fs-decisions`: Starter, `serve`, `--version`, `--help`). Ein Kern-Crate gibt es noch nicht: das Zählen der Stimmen bleibt in `fs-forms-methods` (fs-forms), bis es nach `fs-tally` und `fs-ballot` umzieht (Planschritte D1 und D2); in dieser Version wird nichts verschoben.
- **Hauptansicht (Vorschau).** Die Seite „Decisions“ zeigt ein Termin-Raster nach Art von Doodle (Teilnehmende mal Zeitfenster, Antworten Ja, Wenn nötig, Nein in Worten, Zahlen getrennt, vorgeschlagenes Fenster mit der Regel daneben) und die Liste „Meine Entscheidungen“. Alles sind typisierte Beispieldaten („Beispiel A“ bis „Beispiel D“), gekennzeichnet mit „Vorschau“ (Banner, Fenstertitel) und „Beispiel“; `mode(capabilities)` blendet sie aus, sobald der Server `decision.read` anbietet. - **Fenster.** Seiten Start, Entscheidungen und Was kommt (`--screen start|main|coming`); das Symbol mit 64 px sitzt direkt am Titel; „Ziel:“ vor dem Zielsatz; was nicht gebaut ist, sagt „kommt noch“, die offenen Punkte „geplant, nicht terminiert“.
- **Starter.** `fs-decisions` startet oder ersetzt den Server (Handschlag von `fs-rpc`), lässt das Frontend den Vertrag prüfen (`--check`, Rückgabecode 3 = passt nicht) und fällt mit sichtbarer Meldung auf das Standard-Frontend `simple` zurück. Fehler im Fenster und auf stderr sind ein Code mit Parametern; die Wörter gehören dem Programm (MessageFormat 2, Deutsch und Englisch).
- **Pins, je Bibliothek eine Quelle:** `fs-interfaces` v0.0.27, `fs-rpc` v0.0.2, `fs-components` v0.0.25 (`fs-types` und `fs-objects` durch diese). `.fs-lock-sources.toml` streng. Mindest-Rust 1.89.
- **CI:** `check.yml` und `release.yml` rufen fs-release bei `v0.0.10` auf. Nur Linux (`windows-targets` leer: Unix-Sockets). Release, nachdem der Inhaber die Signier-Umgebung eingerichtet hat.
- Das Symbol (`packaging/net.freesynergy.Decisions.png`, `.desktop`, im Fenster eingebettet); `fs-decisions` hängt vom Paket `fs-decisions-simple` ab (deb `depends`, rpm `requires`).
- Vertrag: Entwurf (`surveys.capnp`, nicht gesperrt). Die Grundfassung erscheint mit diesem Entwurf. Der Fähigkeits-Schlüssel bleibt `surveys` (Anzeigename „Decisions“, ADR 0068).
